Eight-patient free-for-all can change a patient's selected opponent during a committed escape. The previous `EscapeState` held its goal until timeout/arrival even when a different fighter became the target, or when one of two pincer threats was replaced. The local v1 `src/systems/ai.js` documents cancelling manoeuvres whose justification disappears; the native 3D adaptation now tracks target ID / sorted threat IDs inside `EscapeState`. Deterministic unit regressions confirm cancellation for changed IDs and continued motion when only opponent-list order changes. ## P3 live occupancy of an active escape goal (25 November 2026)

In the eight-patient arena, a free destination selected for `relocate` or `pincer` can become occupied by a moving patient during a committed manoeuvre. `EscapeState.choose` now rechecks the current `occupied` list on each simulation tick, using the same per-mode 35/26-unit exclusion radii as initial candidate selection. It cancels the obsolete goal without resetting pincer cooldown, changing RNG draws, modifying strikes, or forcing a result. ## P3 close-contact geometric reengagement (25 November 2026)

A native root distance below .46 m previously stopped automatic pursuit even when the existing static IK + swept-contact preview found **no damageable contact**. This contradicted the already-ported 2D `src/systems/ai.js` rule: if no physical strike is possible, keep closing instead of treating an abstract distance as attack-ready. The change introduces `combat/engagement.ts:pursuitForward` and passes a `failedStrikePreview` flag only when the standard ready/visible/unobstructed/turn checks ran, no strike began, and the patient is upright. It does not run a new expensive geometry query, extend reach, bypass blockers, generate damage, force a result, or override player commands. A successful preview still stops normal approach and goes through the same windup/contact pipeline.

Regression: a two-patient native-core fixture with an armless but two-legged autonomous patient only 0.4 m from an opponent verifies continued pursuit with `StrikeState` remaining idle; pure helper tests also preserve the old standoff without a failed preview, heading and trait scaling. The isolated helper was compiled by TypeScript and passed one Node test; the compiled-core integration regression and six combined TS+Rapier scenarios remain unverified. No full client build was requested or run. This is a cause-specific P3 repair, **not** evidence that all six full-cycle audits are now complete.

## P3 damaged, mobile and disarmed survivors (25 November 2026)

The previous native group AI repeatedly pursued targets when its patient had lost all usable strike sources. Port the existing local v1 `src/systems/ai.js:fighterIntent/fleeAllAttackers` behavior instead: a mobile patient with no usable source avoids armed opponents, holding a chosen point for 1.8 s; when no armed threats remain it resumes patrol. `hasAttackSource` respects legacy arm-only mode, the native head strike, and the two-leg support requirement of a kick. A working upper-arm stump supports crawling but not a missing forearm strike. The scorer keeps the 24 v1 headings and 75/125/170 lengths, tests all armed threats, and uses the native `ArenaNavigation.reachable` and occupied-goal checks.

When P3 perception is enabled, fleeing reacts only to visible threats or a recently remembered armed opponent, avoiding knowledge through opaque walls. Manual input is untouched. No time-based win, arbitrary damage, new locomotion mode or simplified anatomy is introduced. Individual retreat choices are deterministic and only recalculated at expiry, arrival, danger-set change or goal blockage. Existing strike selection and contact pipeline are untouched.

Focused regression module: `3d/core/tests/disarmed.test.mjs` (anatomical sources; headless sight; one-leg fleeing; stump crawl; multi-opponent avoidance; no-weapon patrol). The new pure helper passed isolated strict TypeScript checks and Node assertions; the native-core regression and six integrated TS+Rapier combat cycles still require CI. A scoped 1000-plan wall/navigation microbenchmark ran at approximately 37 ms median with three threats; **not** a full step p95 or client FPS measurement. Full client build was not run locally.
