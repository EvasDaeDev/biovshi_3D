# P4 — полная вместимость восьми авторских 3D-арен

Инкремент от 25 ноября 2026 года. **P4 всё ещё не завершён.** До этого изменения 3D-лаборатория намеренно запускала не более четырёх пациентов, хотя локальная копия оригинального 2D-кода уже валидировала места для полной вместимости каждой карты.

## Источник и реализация

- В **локальной копии** `src/game/location-geometry.js` открыт только неразрушающий экспорт `locationSpawnSlots(location,margin)`; используются **те же** `clearanceTest` и `automaticSpawns`, которые уже были доступны `parseLocation`. 2D алгоритм, геометрия, состав карт и исходное приложение не изменены. Оригинальный внешний репозиторий `EvasDaeDev/biovshi` не затронут.
- `catalog-locations.mjs` загружает все безопасные точки, включая 5–10 позиции, вместе с исходными стартами первой четвёрки. `location-adapter.ts` преобразует их в метры и `NativeLocation.spawnSlots`. Это сохраняет исходный результат старого алгоритма, а не вводит второй генератор.
- `createAuthoredCombatConfig(seed,location,participants)` берёт готовую анатомию, характеры и боевой ИИ `createArenaCombatConfig`. Для девятого и десятого пациентов используются уже существующие шаблоны без создания новых профилей или роботизированной манеры поведения. Идентификаторы уникальны от 0 до N−1.
- В `lab-next/rig.html` доступен выбор числа пациентов «По вместимости» (по умолчанию) или конкретного количества 2–10. Запрос `?scenario=location-ward&patients=10` даёт воспроизводимую 10-пациентную демонстрацию. Запрошенное число выше авторской вместимости ограничивается допустимым максимумом; история пола IndexedDB сохраняется **по ID арены и сессии**, а не по числу персонажей.

## Проверки P4

- `tests/full-capacity-locations.test.mjs` проверяет точное число точек, сохранение исходных четырёх стартов, минимальную дистанцию между всеми участниками, отсутствие стартов внутри выпуклых препятствий и корректный `WorldConfig` для всех карт. Для каждого исходного плана выполняются 240 физических тиков 3D-симуляции; тест ловит NaN, повреждения геометрии, невалидные маршруты и выход активного корня за полигональный контур.
- `scripts/audit-authored-arenas.mjs` — восемь полноразмерных `LabSimulationCore + DebrisWorld(Rapier)` боёв с настоящими отрывами/рагдоллами/конусами и без подмены исхода. По умолчанию CI выполняет **10 симуляционных секунд на каждой карте**, записывает CPU p50/p95/p99, события урона, коллизии, останки, число живых и признак `combat-open` либо `complete`. Бой, который ещё продолжается, **не засчитывается как поражение и не останавливает CI**; нечисловые координаты или проход через геометрию — ошибки. Вручную можно запустить `P4_AUDIT_SECONDS=60 node 3d/core/scripts/audit-authored-arenas.mjs` после компиляции ядра: полноценный 60-секундный аудит каждой карты без клиентской сборки.
- `.github/workflows/3d-preview-pages.yml` сохраняет JSON-отчёт `authored-arena-audit.json` как отдельный Actions-артефакт, затем выполняет **старые шесть эталонных боёв** и Chromium smoke. Браузер дополнительно проверяет 10 пациентов на `ward` и `maze`, 3 на `ring`, выбор четырёх пациентов и обратное переключение.

До получения успешного CI этот инкремент не считать принятым.

## Что всё ещё блокирует закрытие P4

1. Авторский слой реальных **высот и уклонов для существующих восьми локаций**: исходные 2D JSON не несут высот; отдельный диагностический `GradeSurface` уже реализован, но продуктовые высоты не придуманы. Нужно явное 3D описание / редактор.
2. Физически сложные контакты **всех сегментов, опор и ragdoll** со стенами и уклонами, включая сохранение видимой анатомии при переходе между раундами.
3. Запуск **60-секундного** аудита всех восьми арен, сравнение CPU p95/p99, задержек ударов, выхода за границы и застреваний, исправление конкретных найденных регрессий.
4. Общая ручная отладка с пользователем после полного P4. Привязка генераций Башни и игровых экранов остаётся P5, а не оправданием для сокрытия дефектов P4.

Переходить к статусу **«P4 завершён — можно отлаживать»** только после выполнения и проверки этих пунктов.
