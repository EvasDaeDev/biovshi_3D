# Стратегия вычислительного ядра: TypeScript сейчас, Rust/WASM при необходимости

## Решение

Сохраняем **Three.js** для рендера и **Rapier 3D** для динамических останков и обездвиженных тел. Новое приложение и игровые подсистемы пишем на **TypeScript**. Самостоятельное Rust/WebAssembly-ядро **пока не внедряем**: в лабораторном тесте не выявлено узкого места, оправдывающего немедленное переписывание. TypeScript не ускоряет JavaScript во время исполнения — его ценность в проверке контрактов и рефакторинге.

Будущий Rust/WASM должен заменить только наиболее дорогие вычисления после сравнительного профилирования, а не Three.js, камеры, DOM или аудио. Rapier уже использует WASM; не нужно портировать его заново.

## Граница симуляции

`3d/core/src/types.ts` — исходный контракт `SimulationCore`, не привязанный к движку:

- `initialize(WorldConfig)` — создать симуляцию;
- `step(dt, InputFrame)` — выполнить фиксированный шаг;
- `getSnapshot()` — получить самостоятельные `Float32Array` и `Uint32Array` состояния для визуализации;
- `drainEvents()` — забрать подтверждённые события игры;
- `dispose()` — освободить ресурсы.

Координаты: **метры, Y вверх, yaw в радианах**. Управление: W/S задают скорость вдоль локальной оси, A/D и мышь в будущем задают ориентацию. Снимок состояния не должен содержать ссылок на Three.js, Rapier, DOM, WebGL.

`3d/core/src/reference-core.ts` — намеренно маленькая детерминированная реализация для проверки контракта: **не содержит IK, реальных капсул, боёв или ампутаций; не используется действующим стендом**. Производственной симуляцией его считать нельзя.

## Границы владения данными

1. Авторитетное состояние и время — внутри `SimulationCore`, если оно полностью реализовано.
2. Рендер читает состояния двух завершённых тиков, выполняет интерполяцию, не меняет HP и не определяет попадания.
3. ИИ передаёт команды, не меняет позиции костей и физические тела напрямую.
4. Контактный решатель принимает капсулы, отдаёт пары и точки контакта; `DamageResolver` решает, есть ли урон. Один непрерывный контакт не равен нескольким ударам.
5. Оторванные сегменты переходят от кинематической анимации к динамической физике; после стабилизации могут заменяться статическим пологим препятствием. Нельзя одновременно держать динамический и запечённый коллайдер той же части.
6. Форматы сохранений и ID сегментов версионируются, а `body.js` исходной игры остаётся эталоном существующих ключей до их переноса.

## Процедура выбора Rust/WASM

**До переноса** провести 60-секундные записи при 8/16/32/64 пациентах, с полными и повреждёнными скелетами. Измерить p50/p95/p99 по подсистемам: IK, broad phase, narrow phase, разрешение контактов, обновление пола, AI, физика, рендер CPU и GPU. Сравнивать одинаковое число активных капсул.

Первые кандидаты на WASM: пакетные расстояния между капсулами, массовая IK и построение heightmap. Передавать данные через плотные массивы целиком на тик. Исключить тысячи мелких вызовов JS↔WASM. Сравнить TypeScript и Rust по скорости, расходу памяти, размеру загрузки и времени старта на реальных целевых ПК.

**Условие переноса:** устойчивая значимая экономия времени всей симуляции после учёта передачи данных и компиляции WASM, без потери корректности. Если выигрыша нет — оставаться на TypeScript.

## Запуск контракта и тестов

Из корня собранного проекта или стартового пакета:

```bash
cd 3d/core
npm install
npm test
```

`3d/core` — отдельный пакет, не добавляющий TypeScript в зависимости оригинальной 2D-игры. Его `dist/` генерируется локально и не помещается в исходные файлы Git.

## Порядок внедрения

1. Оставить `3d/lab/main.js` как проверенный функциональный эталон.
2. Перенести его обработку ввода и цикл 60 Гц в отдельные модули TypeScript.
3. Выделить структуру пациента и стабильные вращения костей из кода Three.js.
4. Выделить капсульные коллизии и тесты отдельных контактных эпизодов.
5. Выделить Rapier-обломки, конусы и переходы жизненного цикла.
6. Подключить новый `SimulationCore` к Three.js через адаптер снимков состояния.
7. Только после этого переносить повреждения/HP/ИИ из оригинала и оценивать WASM.

Не подменять `reference-core.ts` реальной системой незаметно: контракт содержит только корневые трансформации. Для полноценного рендера требуется расширить снимок стабильным массивом костей и таблицей индексов сегментов, закрепить порядок и написать тесты бинарного формата.
